# Wazuh SIEM & XDR Operations

This document outlines the capabilities and configuration of Wazuh as an open-source Security Information and Event Management (SIEM) and Extended Detection and Response (XDR) platform. It covers agent-manager communications, security features, and how to write custom detection rules.

---

## Part 1: Wazuh Core Architecture

Wazuh provides unified security monitoring, vulnerability detection, and threat intelligence. Its components include:

1.  **Wazuh Agent:** A lightweight system service installed on endpoints. It monitors system logs, file changes (FIM), system inventory, and security configurations, sending telemetry securely to the Manager.
2.  **Wazuh Manager:** The brain of the platform. It collects, parses, and analyzes log data received from agents. It evaluates telemetry against security rules, triggers alerts, and can invoke active responses.
3.  **Wazuh Indexer:** A search engine that indexes and stores alerts generated by the manager.
4.  **Wazuh Dashboard:** The web UI for visualization, dashboard analysis, and administration.

---

## Part 2: Key XDR Features

### 1. File Integrity Monitoring (FIM)
FIM monitors key system files, directories, and Windows Registry keys. It records changes in permissions, file contents, hashes, and ownership, alerting on unauthorized modifications.
*   **Analogy:** A security camera watching a vault. Any time a file is touched or modified, a snapshot is taken and audited.

### 2. Active Response
Active Response enables automatic mitigation actions on endpoints when specific high-severity rules are triggered (e.g., block an attacker's IP on the local firewall, or isolate a compromised VM).
*   **Analogy:** A smart lock that automatically bolts the door if the alarm detects forced entry.

### 3. Security Configuration Assessment (SCA)
SCA performs regular system scans to verify compliance with hardening guides, benchmarks (like CIS), and security policies, identifying weak configuration points.

## Part 3: Creating Custom Rules (The Mimikatz Case Study)

In our **SOC Automation Lab**, we configured Sysmon to monitor a Windows 11 endpoint, which forwarded telemetry to the Wazuh Manager. To detect the execution of **Mimikatz** (a credential dumping tool), we created a custom Wazuh rule.

### Writing Custom Rules (`local_rules.xml`)
Custom rules are added to `/var/ossec/etc/rules/local_rules.xml` on the Wazuh Manager. The manager parses incoming logs and compares them against these criteria.

We wrote **Rule 100002** to alert on any process creations matched as Mimikatz:

```xml
<group name="sysmon,security_event,">
  <!-- Parent Rule: Matches Sysmon Event ID 1 (Process Creation) -->
  <rule id="100002" level="15">
    <if_sid>61603</if_sid>
    <field name="win.eventdata.originalFileName" type="pcre2">(?i)mimikatz\.exe</field>
    <description>Critical Alert: Mimikatz Credential Dumping Tool Detected on Endpoint</description>
    <mitre>
      <id>T1003</id>
    </mitre>
  </rule>
</group>
```

*   **`<rule id="100002" level="15">`:** Creates a new rule. Level `15` is the highest severity level in Wazuh, representing a critical, high-impact compromise.
*   **`<if_sid>61603</if_sid>`:** Links this rule to the parent rule `61603` (which is the default Wazuh rule for Sysmon Event ID 1: Process Creation).
*   **`<field name="...">`:** Uses Regex (`pcre2`) to look for `mimikatz.exe` in the original file name field. This ensures that even if an attacker renames the executable to `chrome.exe`, the underlying original metadata (`originalFileName`) is still detected.
*   **`<mitre>`:** Maps the alert to the MITRE ATT&CK framework technique **T1003 (OS Credential Dumping)**, providing immediate threat context to SOC analysts.

---

## Part 4: Automated Threat Handling Integration

Once Rule `100002` triggered a Level 15 alert, Wazuh forwarded this alert event in JSON format via Filebeat to our **Shuffle SOAR** platform. 

This automation pipeline bypassed manual analysis, instantly enriching the threat telemetry and initiating incident response procedures without agent downtime.
